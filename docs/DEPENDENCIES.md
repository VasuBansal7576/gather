# Dependency advisories

## postcss (fixed: 8.4.31 → 8.5.23 via `overrides`)

`next@15.5.25` pins `postcss@8.4.31` exactly, which is covered by four high
advisories (GHSA-qx2v-qp2m-jg93 `</style>` XSS, GHSA-6g55-p6wh-862q,
GHSA-fxqj-rqcc-2cmp, GHSA-r28c-9q8g-f849 — all `<=8.5.22`). There is no
patched 8.4.x release; the fixed floor is `8.5.23`.

`package.json` carries `"overrides": { "postcss": "8.5.23" }` — a pinned,
minimal in-8.x patch that replaces next's exact pin. Verified compatible:
`npm ci` + `npm run build` compiles the app CSS
(`.next/static/css/*.css` emitted, minified) under 8.5.23 and the full test
suite passes. `npm audit fix --force` was rejected — it would install
`next@16.x`, a breaking migration, not a patch.

## sharp (fixed: 0.34.5 → 0.35.4 via lockfile)

next declares `sharp` as an optional dependency with range
`^0.34.3 || ^0.35.4`, so `0.35.4` (the fixed release for GHSA-f88m-g3jw-g9cj
libvips CVEs and GHSA-rgj7-g3m4-5g8c libheif) resolves inside the declared
range with no manifest change — `npm update sharp` produced the lock entry.
Verified functional: `require('sharp')` loads libvips 8.18.6 and encodes a
PNG. sharp's own `install/check.js` script remains unapproved in this
environment's allowScripts gate; the 0.35.x platform packages
(`@img/sharp-*`) ship prebuilt binaries, so the gate does not affect it.

## Invariants

- No direct dependency changed; versions stay pinned, lock regenerated by
  npm (`npm update`/`npm ci`), never hand-edited.
- `npm audit` after the change: 0 vulnerabilities.
